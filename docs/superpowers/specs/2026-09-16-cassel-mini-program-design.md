# 卡塞尔学院微信小程序设计规格

## 状态

已获用户确认，采用原生微信小程序方案，第一版先跑通完整展示流程。

## 背景

当前项目是一个原生 HTML/CSS/JavaScript 单页官网，主题为“卡塞尔学院 / CASSEL ACADEMY”。页面内容包含学院档案、院系体系、校历观测、招生入口和联系表单，视觉基调为深夜蓝黑、旧金色、暗红警示色和档案式等宽标签。

本次工作在不破坏现有静态官网的前提下，新增一个可被微信开发者工具直接导入的原生小程序目录。

## 目标

- 将官网主要内容迁移到微信小程序原生页面。
- 保留现有官网的核心文案、视觉气质、徽记、星轨装饰和卡片结构。
- 使用小程序原生路由、TabBar、表单控件和触摸交互。
- 不依赖外部 CDN、字体、第三方包或后端接口。
- 让开发者工具可以在未配置正式 AppID 的情况下完成本地预览。

## 第一版不包含

- 用户登录、注册和个人中心。
- 预约、支付、收藏、消息推送。
- 云开发、服务器接口和真实表单入库。
- 管理后台和内容管理系统。
- 将现有官网改造成前端框架工程。

## 页面与导航

小程序包含五个页面：

1. `pages/index/index`：首页。展示学院徽记、主标语、学院简介、核心 CTA 和内容入口。
2. `pages/archive/archive`：学院档案。展示成立年份、在册校区、安全等级和档案说明。
3. `pages/departments/departments`：院系体系。展示执行部、龙文研究院和炼金工坊，并支持卡片内展开详情。
4. `pages/calendar/calendar`：校历观测。展示公开讲座、秋季招生档案和现场测试时间线。
5. `pages/contact/contact`：联系学院。展示联系信息并提供原生表单。

底部 TabBar 使用四个入口：

- 首页 → `pages/index/index`
- 档案 → `pages/archive/archive`
- 校历 → `pages/calendar/calendar`
- 联系 → `pages/contact/contact`

院系体系不独占 Tab，由首页和档案页中的导航按钮通过 `wx.navigateTo` 进入。Tab 页面之间使用 `wx.switchTab`，普通页面使用 `wx.navigateTo`；不再使用网页锚点。

## 工程结构

现有静态官网继续保留在项目根目录；新增内容放入 `miniprogram/`：

```text

│  ├─ index/

`project.config.json` 放在项目根目录，设置 `miniprogramRoot` 为 `miniprogram/`，当前使用微信测试号 AppID 进行开发和真机预览；正式发布前由项目所有者替换为正式 AppID。

## 数据与组件设计

`data/academy.js` 集中提供以下静态数据：

- `academyMeta`：学院名称、英文名、学院编号、状态、主标题和简介。
- `archiveStats`：成立档案、校区数量、安全等级。
- `departments`：院系编号、英文标识、名称、描述和详情。
- `calendarItems`：日期、类型、标题、说明和开放状态。
- `contactDetails`：邮箱、电话、开放时间。

页面通过 `require` 引入数据，再通过 WXML 数据绑定传给组件。组件只负责渲染和局部交互，不直接读取页面级状态。

组件职责：

- `section-heading`：统一章节编号、英文标签和中文标题层级。
- `archive-stat`：渲染单条档案统计项。
- `department-card`：渲染院系卡片，管理自身展开/收起状态。
- `timeline-item`：渲染时间线条目和开放状态。
- `primary-button`：统一主按钮样式并通过事件向页面传递点击行为。

## 视觉系统

全局样式在 `app.wxss` 中维护，页面样式放在各页面的 WXSS 中：

- 背景：`#080d14` 深夜蓝黑。
- 主表面：`#111c27` 和 `#182532`。
- 主强调色：`#c6a66a`，亮金色为 `#e5cf95`。
- 警示色：`#8e3f45`。
- 信息色：`#87a6ab`。
- 正文：`#eef0e9`，辅助文字使用低对比度灰蓝。
- 标题使用系统衬线字体栈，正文使用系统无衬线字体栈，不加载网络字体。

页面统一使用细边框、编号标签、轻渐变和档案式间距。装饰性的徽记和星轨作为本地 SVG 资源使用，所有核心信息同时以文本呈现，避免装饰资源异常时影响可读性。

移动端以单列布局为主，内容区左右留白约 32rpx，卡片和按钮保持足够触摸区域；不使用横向滚动承载核心内容。

## 交互与状态

### 页面交互

- 首页 CTA 跳转至档案页、院系页或联系页。
- 院系卡片点击后在当前卡片内展开详情，再次点击收起。
- TabBar 负责四个主页面切换。
- 页面滚动采用微信原生滚动，不实现网页式固定返回顶部按钮。
- 动画仅保留轻量淡入、边框强调和卡片展开，避免复杂持续动画。

### 联系表单

表单字段为姓名、邮箱、主题和记录内容，全部必填。提交时按以下顺序处理：

1. 读取表单值并去除首尾空白。
2. 检查必填字段。
3. 使用本地规则检查邮箱格式。
4. 校验失败时在表单下方显示明确提示，并将焦点保留在当前页面。
5. 校验成功时显示“记录已封存” Toast，清空表单并恢复初始状态。

第一版不发起网络请求，不保存到云端，也不伪造真实提交成功以外的后台状态。页面文案会明确这是本地演示表单；接入后端时只替换提交处理层。

## 数据流

       页面 Page
          ↓
   data/academy.js 静态数据
          ↓

contact 页面表单

          ↓
  Toast 提示并清空表单
```

## 异常与兼容处理

- 静态数据不存在时，页面显示空状态文本，不渲染破损卡片。
- 装饰资源加载失败时，保留背景、边框和文字信息。
- 表单错误不依赖网络状态，直接在页面内反馈。
- 页面不使用浏览器 DOM、锚点、`window`、`document` 或外部脚本。
- 不使用第三方 npm 依赖，降低开发者工具构建和审核风险。
- `project.config.json` 不包含真实 AppID、密钥或环境凭证。

## 验收标准

### 功能

- 微信开发者工具可以直接导入项目并识别 `miniprogram/` 为小程序根目录。
- 首页、档案、校历、联系四个 Tab 均可正常切换。
- 首页和档案页可以进入院系体系页。
- 院系卡片可以展开和收起详情。
- 联系表单可以校验必填字段和邮箱格式。
- 表单成功后出现 Toast 并清空输入内容。

### 视觉与适配

- 主要页面保持深夜蓝黑、旧金色、暗红和档案式视觉。
- 手机窄屏下内容单列排列，没有横向溢出。
- 触摸控件尺寸适合手指操作，文字不被截断。
- 无外部图片、字体、CDN 或接口请求。

### 代码质量

- 文案和重复内容集中在数据文件或组件中。
- 页面逻辑与展示组件职责清晰。
- WXML 不包含网页 DOM API 或不受支持的浏览器脚本。
- 所有页面路径、TabBar 路径和组件引用保持一致。

## 实现顺序

1. 创建小程序根配置和全局样式。
2. 整理静态学院数据与本地装饰资源。
3. 创建通用组件。
4. 实现首页和 Tab 页面。
5. 实现院系展开交互和联系表单校验。
6. 做静态结构检查、路径检查和开发者工具导入前检查。
7. 根据可验证结果修复问题，并记录最终运行方式。
